Discussion on BLUE

According to the Gauss-Markov theorem, the Ordinary Least Squares (OLS) estimator is the Best Linear Unbiased Estimator (BLUE) provided that the following assumptions hold: - Linearity: The relationship between the dependent and independent variable is linear. - Independence: The error terms are independent. - Homoscedasticity: The error terms have constant variance. - Unbiasedness: The error term has an expected value of zero.

In each of these simple regression models, if the assumptions above are met, the OLS estimates will be BLUE, meaning they have the smallest variance among all linear unbiased estimators. However, if any of these assumptions are violated—for instance, if there is heteroscedasticity or non-linearity—the estimators may no longer be considered BLUE.

Checking for Multicollinearity using VIF

We will now check for multicollinearity among the predictors in the multiple regression model using the Variance Inflation Factor (VIF). A common rule of thumb is that VIF values greater than or equal to 10 indicate problematic multicollinearity. We will iteratively remove the variable with the highest VIF until all remaining variables have VIF < 10.

# Load the car package for VIF calculation
library(car)
## Loading required package: carData
# Check if the multiple_model exists and has more than one predictor
if (exists("multiple_model") && length(coef(multiple_model)) > 2) {

  # Calculate initial VIF values
  vif_values <- tryCatch(
    vif(multiple_model),
    error = function(e) {
      cat("Error calculating VIF: ", e$message, "\n")
      return(NULL)
    }
  )

  if (!is.null(vif_values)) {
    cat("Initial VIF values:\n")
    print(vif_values)

    # Iteratively remove variables with VIF >= 10
    current_predictors <- names(vif_values)
    while(any(vif_values >= 10, na.rm = TRUE)) {
      # Find variable with highest VIF
      max_vif_var <- names(which.max(vif_values))
      cat("\nRemoving variable with highest VIF:", max_vif_var, "(VIF =", round(max(vif_values, na.rm = TRUE), 2), ")\n")

      # Update predictor list
      current_predictors <- setdiff(current_predictors, max_vif_var)

      # Check if there are enough predictors left
      if (length(current_predictors) < 1) {
        cat("Not enough predictors left to build a model after removing high VIF variables.\n")
        multiple_model <- NULL # Set model to NULL as it's no longer valid
        break
      }

      # Refit the model with remaining predictors
      formula_updated <- as.formula(paste("mpg ~", paste(current_predictors, collapse = " + ")))
      multiple_model <- lm(formula_updated, data = train_data)

      # Recalculate VIF for the new model
      # Need at least 2 predictors to calculate VIF
      if (length(current_predictors) >= 2) {
         vif_values <- tryCatch(
           vif(multiple_model),
           error = function(e) {
             cat("Error calculating VIF after update: ", e$message, "\n")
             return(NULL) # Stop iteration if VIF calculation fails
           }
         )
         if (is.null(vif_values)) break # Exit loop if VIF calculation failed
         cat("Updated VIF values:\n")
         print(vif_values)
      } else {
         cat("Only one predictor remaining, VIF calculation not applicable.\n")
         vif_values <- c(0) # Set VIF to 0 to exit loop
      }
    }

    # Display the final model summary if a valid model exists
    if (!is.null(multiple_model)) {
       cat("\nFinal Multiple Linear Regression Model Summary (after VIF check):\n")
       print(summary(multiple_model))
    }
  }
} else if (exists("multiple_model") && length(coef(multiple_model)) <= 2) {
  cat("Multiple regression model has only one predictor or intercept. VIF check is not applicable.\n")
  cat("Final Model Summary:\n")
  print(summary(multiple_model))
} else {
  cat("Multiple regression model was not built (likely due to no significant predictors initially).\n")
}

Model Performance Metrics

# Check if the final model exists before calculating metrics
if (!is.null(multiple_model)) {
  # Function to calculate performance metrics
  calculate_metrics <- function(actual, predicted) {
    rmse <- sqrt(mean((actual - predicted)^2, na.rm = TRUE))
    mae <- mean(abs(actual - predicted), na.rm = TRUE)
    list(RMSE = rmse, MAE = mae)
  }

  # Get predictions on training data
  train_pred <- predict(multiple_model, newdata = train_data)

  # Get predictions on testing data
  # Ensure test_data has the same predictors as the final model
  final_predictors <- names(coef(multiple_model))[-1] # Exclude intercept
  if (all(final_predictors %in% names(test_data))) {
     test_pred <- predict(multiple_model, newdata = test_data)
     test_actual <- test_data$mpg
  } else {
     cat("Warning: Not all predictors from the final model are present in the test data. Cannot calculate test metrics accurately.\n")
     test_pred <- NA
     test_actual <- NA
  }


  # Calculate metrics for training data
  train_metrics <- calculate_metrics(train_data$mpg, train_pred)

  # Calculate metrics for testing data if possible
  if (!any(is.na(test_pred))) {
     test_metrics <- calculate_metrics(test_actual, test_pred)
  } else {
     test_metrics <- list(RMSE = NA, MAE = NA)
  }


  # Display results
  cat("\nModel Performance Metrics:\n")
  model_summary <- summary(multiple_model)
  cat("\nTraining Data:")
  cat("\n - R-squared:", round(model_summary$r.squared, 4))
  cat("\n - Adjusted R-squared:", round(model_summary$adj.r.squared, 4))
  cat("\n - RMSE:", round(train_metrics$RMSE, 4))
  cat("\n - MAE:", round(train_metrics$MAE, 4))

  cat("\n\nTesting Data:")
  if (!is.na(test_metrics$RMSE)) {
    cat("\n - RMSE:", round(test_metrics$RMSE, 4))
    cat("\n - MAE:", round(test_metrics$MAE, 4))
  } else {
    cat("\n - Metrics could not be calculated for test data.")
  }

} else {
  cat("\nFinal model does not exist, cannot calculate performance metrics.\n")

LASSO Regression

LASSO (Least Absolute Shrinkage and Selection Operator) is another method to handle multicollinearity and perform variable selection by shrinking some coefficients exactly to zero.

# Load the glmnet package
# install.packages("glmnet") # Uncomment if not installed
library(glmnet)
## Loading required package: Matrix
## Loaded glmnet 4.1-8
# Prepare data matrices (using all original predictors for LASSO)
# Ensure 'mpg' is excluded from predictors
all_predictors <- setdiff(names(mtcars), "mpg")
x_train_lasso <- as.matrix(train_data[, all_predictors])
y_train_lasso <- train_data$mpg
x_test_lasso <- as.matrix(test_data[, all_predictors])
y_test_lasso <- test_data$mpg

# Perform cross-validation to find the optimal lambda (penalty parameter)
# alpha = 1 specifies LASSO regression
set.seed(123) # for reproducibility of cv.glmnet
cv_fit <- cv.glmnet(x_train_lasso, y_train_lasso, alpha = 1)
## Warning: Option grouped=FALSE enforced in cv.glmnet, since < 3 observations per
## fold
# Plot the cross-validation results (MSE vs. log(lambda))
plot(cv_fit)

cat("Optimal lambda (lambda.min) based on cross-validation:", cv_fit$lambda.min, "\n")
## Optimal lambda (lambda.min) based on cross-validation: 0.3821765
cat("Optimal lambda (lambda.1se) based on cross-validation:", cv_fit$lambda.1se, "\n")
## Optimal lambda (lambda.1se) based on cross-validation: 1.693279
# Fit the final LASSO model using the optimal lambda (lambda.min is often preferred)
lasso_model <- glmnet(x_train_lasso, y_train_lasso, alpha = 1, lambda = cv_fit$lambda.min)

# Display the non-zero coefficients selected by LASSO

Discussion on Residual Analysis Results

  • Linearity: Examine the “Residuals vs Fitted” plot. Ideally, the points should scatter randomly around the horizontal line at 0, with no discernible pattern (like a curve). A pattern suggests the linearity assumption might be violated.
  • Independence: The Durbin-Watson test statistic should ideally be close to 2. Values significantly lower than 2 suggest positive autocorrelation, while values significantly higher suggest negative autocorrelation. This test is most relevant if the data has a natural order (e.g., time series). The “Residuals vs Order” plot can also visually hint at autocorrelation if patterns emerge.
  • Normality: The “Normal Q-Q Plot” should show points falling approximately along the straight line. Deviations, especially at the tails, indicate non-normality. The Shapiro-Wilk test provides a p-value; if p < 0.05, we reject the null hypothesis of normality.
  • Equal Variance (Homoscedasticity): The “Scale-Location Plot” should show points randomly scattered with roughly constant vertical spread. A funnel shape (widening or narrowing spread) indicates heteroscedasticity (non-constant variance). The Breusch-Pagan test provides a p-value; if p < 0.05, we reject the null hypothesis of homoscedasticity.

Whether the final model (derived from LASSO and potentially refined by diagnostics) is suitable for prediction depends on several factors:

  1. Residual Analysis Results: If the LINE assumptions are reasonably met (especially linearity and homoscedasticity), the model’s predictions are more likely to be reliable and unbiased on average. Significant violations suggest the model might not capture the underlying relationship well, leading to poor predictions.
  2. Performance on Test Data: The key indicator is how well the model performs on unseen data (the test set). Look at the RMSE and MAE calculated for the testing data in the “Model Performance Metrics” section for the LASSO model. Lower values indicate better predictive accuracy. If the test RMSE/MAE are substantially higher than the training RMSE/MAE, it suggests overfitting.
  3. Model Complexity vs. Interpretability: LASSO performs variable selection, potentially leading to a simpler model than the initial multiple regression. Simpler models can sometimes generalize better. However, the coefficients from LASSO are shrunk and might be biased (not BLUE), which is a trade-off for variance reduction and variable selection.
  4. Context and Purpose: Is the goal purely prediction, or also understanding the precise effect of each variable? For pure prediction, if test set performance is good and diagnostics are acceptable, the model can be used. If interpretation of coefficients is crucial, the potential bias in LASSO coefficients needs consideration.

Conclusion: Yes, you can likely use this model for prediction if the residual analysis does not reveal major violations of assumptions and the performance metrics on the test dataset (RMSE, MAE) are acceptably low for your purpose. The LASSO approach often yields models with good predictive performance, especially when dealing with multicollinearity or high-dimensional data.

Interpretation of Prediction Accuracy Indices

  • R-squared (Test): This value (ranging from 0 to 1) indicates the proportion of the variance in the test set’s mpg that is predictable from the independent variables included in our final model. A higher R-squared suggests that the model explains a larger portion of the variability in the unseen data. For example, an R-squared of 0.75 means the model explains 75% of the variance in mpg on the test set.
  • RMSE (Root Mean Square Error) (Test): This is the standard deviation of the prediction errors (residuals) on the test set. It measures the average magnitude of the errors in the units of the dependent variable (mpg). A lower RMSE indicates a better fit and more accurate predictions. For instance, an RMSE of 2.5 means that, on average, the model’s predictions are about 2.5 mpg away from the actual values.
  • MAE (Mean Absolute Error) (Test): This measures the average absolute difference between the predicted values and the actual values on the test set. Like RMSE, it’s in the units of mpg, and lower values are better. MAE is less sensitive to large outliers compared to RMSE. An MAE of 2.0 means the average absolute error of prediction is 2.0 mpg.

Overall Assessment: By comparing these test set metrics (R-squared, RMSE, MAE) to the corresponding metrics calculated on the training data earlier, we can assess potential overfitting. If the test metrics are significantly worse (e.g., much lower R-squared, much higher RMSE/MAE) than the training metrics, the model might be overfit to the training data and may not generalize well. If the metrics are reasonably close, it suggests the model generalizes well to new, unseen data. The absolute values of RMSE and MAE provide a sense of the typical prediction error magnitude.

Which prediction is correct (Training vs. Testing Data)?

The question asks about predictions based on training and testing data. Here’s the clarification:

  1. Model Training: The model (whether it’s the VIF-refined multiple_model or the LASSO-derived final_lm_model) is always built using the training data. This is where the model learns the relationships between predictors and the outcome (mpg).
  2. Model Evaluation: The testing data is used only to evaluate how well the trained model generalizes to new, unseen data. We calculate metrics like R-squared, RMSE, and MAE on the test set to get an unbiased estimate of its predictive performance. We do not typically re-train a separate model on the test data for prediction purposes.
  3. Prediction: When predicting for a new data point (like the 6000 lbs car), we use the model trained on the training data (final_lm_model in our latest code).

Therefore, the prediction generated using final_lm_model (which was derived from the training data analysis) is the relevant prediction from our developed model. The concept of a prediction “based on testing data” doesn’t apply in the sense of using a model trained on test data. The test data’s role was purely for evaluation.

Reliability: As noted in the code output, predicting for a car with wt=6 is an extrapolation because the maximum weight in the original mtcars dataset (and thus likely in the training/test sets) is significantly lower. Extrapolated predictions are inherently less reliable than predictions made within the range of the training data, as the learned relationships might not hold true far outside that range. The calculated MPG value should be treated with caution.
